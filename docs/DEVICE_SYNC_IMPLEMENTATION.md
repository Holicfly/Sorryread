# 单设备局域网同步：实施记录

开发前回档提交：`72de07f`。本阶段由用户确认：仅同步收藏、最近阅读和全部阅读位置（包括普通网页／章节 URL 的进度），不传正文、目录文件、封面、设置、书签笔记。手机阅读页下一阶段实现，移除全部示例书籍，显示真实同步书籍并保留原三列色块风格。

## 已确认的交互

- 手机同步页保留顶部状态、上次同步、自动同步说明，以及立即同步／查看记录／断开连接三个操作。不显示同步内容开关、同步方式开关或底部断开行。
- 双端一对一。未配对显示连接新设备；已配对只显示设备信息及删除当前连接设备，设备行不可展开。
- 扫描电脑二维码后，通过局域网 TLS 验证、电脑确认、保存身份完成配对。之后启动和网络恢复时自动发现并连接。
- 断开仅暂停本次运行，保留配对；可重新连接，下次启动自动恢复。删除设备解除配对，保留业务数据；对端离线时也可本机删除，对端通过认证失败或在电脑端解除配对恢复。
- 电脑设置菜单新增设备互联，下设当前状态（已连接绿点／未连接红点）与二维码展示；二维码窗口可解除当前配对，防止丢失手机后被锁定。
- 正常更新覆盖已知旧进度；真正并发修改保留候选，由用户选择。取消收藏、移出最近阅读跨端传播；缓存清理不改变业务状态。
- 前台异步自动同步；后台按 Android 调度条件尽力补齐，不承诺被终止后实时同步，恢复前台补齐。

## 结构与恢复

### 电脑设备互联窗口改版

按用户的已连接／未连接参考图重做弹窗，删除“同步范围”整栏及旧范围说明。采用独立标题栏、状态标题、配对设备卡片／二维码卡片和通栏操作按钮；亮暗主题动态切换，小窗口可垂直滚动。已配对但离线仍保留设备信息和解除配对入口，二维码过期后隐藏并提示刷新。首次未配对打开时自动生成二维码；已有窗口中再次选择二维码菜单可刷新显示。

本次只调整窗口展示与入口交互，同步协议和数据合并逻辑未改。185 项桌面断言通过，其中包含亮暗两种主题、两种展示状态、已配对离线、二维码过期与紧凑布局检查。四张实际 WPF 渲染预览保存在 artifacts/device-link-ui/；预览二维码为无效合成数据。可运行版本输出到 publish/Sorryread-1.2.0-sync-ui/。

### 设备窗口尺寸、打开卡顿与退出残留修复

- 使用说明实际窗口为 430×340（含透明边距），设备互联默认改为 400×300，比其可见边框也小。未连接时二维码和状态／操作并排，已配对时显示紧凑设备卡片；切换状态不再放大窗口。亮暗主题、两种状态及小尺寸滚动共 186 项桌面断言通过。
- 首次打开时，原先在 Loaded 回调中同步执行证书、Kestrel、网卡枚举和二维码生成，可能推迟首帧。现在先让窗口渲染，证书／服务启动和二维码编码均在线程池完成，只将冻结的图像交给界面。
- 退出时，原来的 DisposeAsync 捕获 WPF 上下文，而 App.Exit 又在界面线程 GetResult 等待，形成死锁，数据库和单实例锁也无法继续释放。服务关闭现为线程池任务，所有内部 await 不回到界面线程；同一启动信号量串行化启动与清理，并拒绝退出后的新配对请求。
- 旧发布程序集作为对照，在隔离子进程的未完成配对请求场景中复现退出挂起（十秒未结束）；只结束该测试子进程。修复版通过五次真实 WPF Application.Exit 子进程测试：二维码就绪、启动中、配对等待中、启用 mDNS、再次启动。每次均自然结束并释放测试单实例锁。测试不连接用户数据库，不终止用户应用。日志见 artifacts/device-link-lifecycle-tests.log 与 artifacts/device-link-before-fix-result.txt。
- 修复版本更新到原 publish/Sorryread-1.2.0-sync-ui/ 目录，发布时保留 Data，核对数据库及配对文件哈希一致。

- 桌面 ReaderDatabase.Sync.cs：独立同步表、迁移备份、事务、完整状态、日志和业务投影。原有数据目录继续使用，新增表不替换数据库文件。首次已有业务数据迁移时创建 .before-device-sync-v1.bak。
- 手机 data/ 使用 Drift，生产连接在后台打开。已确认发送操作可清理，状态和删除标记保留；电脑保留最近约 10000 条本地变更，旧游标走快照。日志双方仅保留最近 200 条。
- 新配对先上传手机完整状态，再拉取电脑快照；包括手机从以前配对电脑收到的记录，避免换设备遗漏。快照缺失实体不视为删除。
- 证书与电脑配对记录使用当前 Windows 用户 DPAPI，手机凭据使用系统安全存储；Android 禁用备份。二维码两分钟、上传会话五分钟有效。接收端只允许局域网来源，业务请求还需通过配对认证。
- 界面始终区分断开与删除。电脑丢失旧手机时，可从设备互联窗口解除配对。进度冲突在两端均可显式选择，接收新位置不会跳动当前电脑正文。
- 工程排除 mobile/、shared/、tests/ 和 artifacts/，避免测试生成的 XAML 被 WPF 默认规则重复编译。

- 二维码改为矢量绘制：保留 4 模块静区，每个模块固定占用整数个设备像素（96 DPI 下 2 像素），三个定位图案做圆角，白底圆角卡片加浅阴影。旧实现把位图按非整数倍缩放，模块边缘有 25%～31% 的像素是灰边；新绘制降到 0.4%。窗口由 400×300 收为 400×272，二维码区由 202 缩到 174～182，卡片下方显示有效期倒计时，已配对时整列收起让设备卡片占满宽度。
- 验证不只靠“看起来能扫”：本机实际渲染的 170px 二维码由 zxing-cpp 直接解出完整配对 JSON（含地址、指纹、令牌），三倍到八倍相机模拟（缩放、模糊、噪点、70% 对比度）同样解出。测试新增逐模块对照、定位图案 1:1:3:1:1 扫描线、设备像素整数倍、无滚动条和倒计时断言，共 202 项桌面断言通过；预览见 artifacts/device-link-qr/。
- 配对二维码只放 IPv4 局域网地址（最多 3 个），机器没有 IPv4 时才退回非链路本地 IPv6。此前把 fe80:: 链路本地地址也写进二维码，手机端没有 zone id 无法连接，却让二维码从 77 个模块涨到 89 个。协议字段、校验和手机端 1～8 个地址的约束未改。

## 重现隔离网络联调

### 电脑重启后无法恢复连接：修复记录

- 原服务每次以端口 0 启动，导致手机缓存的地址在电脑退出后失效；原重启测试创建客户端时直接使用新端口，漏测了缓存地址。保留旧端口的回归检查先复现失败（artifacts/reconnect-before.log），现将实际端口原子保存到 Data/DeviceLink/port.txt 并优先复用。端口被其他程序占用时回退到新端口、保存新值并重新广播；无效配置安全恢复。退出时发送 mDNS goodbye，证书、配对凭据和阅读数据不变。
- 原手机发现依赖系统返回的单一主机地址，不能保证包含多网卡电脑的 Wi-Fi 地址。桌面 mDNS TXT 新增 a 字段，携带与二维码相同的最多三个局域网地址；手机优先读取它，过滤公网和缺少作用域的 fe80:: 地址，仍在 TLS 认证前核验证书指纹。协议接口、单设备约束与合并语义不变。
- 手机原生发现的启动、查询、停止均设置等待上限；取消可立即结束等待，迟到的发现句柄只清理自身，不影响下一次搜索。前台失败重试等待间隔从最长五分钟收为三十秒。Android 后台调度规则不变。
- C# 通过缓存端口复用、被占用时回退、回退值持久化、损坏配置恢复、HTTPS 与九个 WPF 子进程场景。Flutter 24 项测试通过，显式联网测试默认跳过；新增八项发现／重试测试，analyze 无问题。原二维码／窗口 525 项桌面断言通过。日志分别为 artifacts/reconnect-desktop-regression.log、artifacts/reconnect-flutter-tests.log、artifacts/reconnect-flutter-analyze-final.log、artifacts/reconnect-ui-tests.log。

### 联调命令

先发布 tests/DeviceSync.Tests，再运行其 exe 的 --serve <隔离输出目录>。添加 --loopback 时只用于本机／USB 转发测试，不广播发现；不带此参数时使用真实局域网地址及 mDNS。测试服务仅操作合成数据并自动确认配对，生产服务仍要求电脑可见确认。

启动手机 integration_test/lan_probe_test.dart（flutter drive + test_driver/screenshots.dart），另一个终端执行 tests/DeviceSync.Tests/Send-PhoneTestTicket.ps1，提供 DeviceId、Adb、HostDirectory 和 TestLog。脚本等待测试开始，再刷新票据，向调试应用私有目录注入二维码图像与 JSON，不打印 token。无线测试不设置 USB 端口转发；报告将分别记录原生图像解码、发现匹配数量与 HTTPS 对账结果。

Windows 上运行 test/sync_live_test.dart 时，SORRYREAD_SYNC_TICKET 指向隔离服务 pairing.json，覆盖 C#／Dart 双向修改、离线并发、显式选择及重试去重。测试数据和产物均放 artifacts/ 或系统临时目录，不能提交。
