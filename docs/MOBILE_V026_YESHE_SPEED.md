# 夜社书目缓存提速（2026-10-28）

## 范围与步骤

用户反馈 0.2.5 缓存过慢，允许手机调试；随后明确选择只优化并发，不在 APK 中预置书目。保留本地数据库、后台任务、暂停续传和本地搜索，不引入云端索引服务。

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 1 | 旧版代码和当前站点 | 固定等待耗时、网络与手机基准 |
| 2 | 基准结果和旧检查点 | 有上限的并发预取、连续页序提交 |
| 3 | 并发中的失败与取消 | 限流退避、自动降速、取消所有请求与可靠续传 |
| 4 | 当前任务的实际处理速度 | 修正 ETA、显示速度与当前并发数 |
| 5 | 完整功能 | 手机对比、全量核对、同签名升级 APK 与下载链接 |

## 研究结果

- 旧实现串行下载，每页成功后固定等待 650 毫秒；仅 841 页等待就需约 9.1 分钟。页面请求、解析和写入还会增加时间。
- Python 小样本每组 12 页，均返回 HTTP 200、每页 30 个链接：新建连接加 650 毫秒等待 26.207 秒；单路显式复用连接无等待 4.790 秒；两路 3.593 秒；四路 2.278 秒。这个探针不等同 Android：Android 的 `HttpURLConnection` 本身可以复用连接池，不能据此声称旧 Android 每次都重新 TLS 握手。
- 公开 robots.txt 返回允许抓取；尝试公开文章列表 API 时只返回“域名未授权”，因此不使用或绕过该接口，继续抓取公开小说分页。
- 真实手机旧版：24 页约 68.541 秒，0.350 页／秒。当时目录共 25,266 本、843 页，按样本吞吐外推全量约 40 分钟。此处不是旧版全量计时结果。

## 实现

- 最多 4 个工作线程，滑动窗口最多保留 4 个未提交分页；先读取当前断点的第一页确定范围，再生成同站连续分页。全部请求共享最少 200 毫秒的启动间隔，避免没有上限地向站点发送请求。取消原来逐页固定等待。
- 工作线程只下载、解压和解析。协调线程严格按连续页序提交；较后页面先返回时暂存在有界窗口中，遇到缺页失败不提交后续结果。原有 `next/pages` 与书目在同一事务中保存，因此兼容旧版断点，无需清空或重建已有缓存。
- 写库按页使用预编译插入语句，删除嵌套元数据事务；保持逐页原子性。通知最多约每秒更新，避免并发后每页高频刷新通知。
- 暂停／取消同时中止全部连接、队列和工作线程；迟到响应不能继续写入。退出后仍能使用本地书名搜索。
- 429、408、500、502、503、504 有上限重试，并自动降到单路；遵守 Retry-After 的秒数或 HTTP 日期，等待期间所有线程共同暂停发起新请求。成功 8 次后逐步恢复到 2 路，再成功 8 次恢复到 4 路。401／403 等不自动反复尝试。
- 很长的 Retry-After 保存到本地并暂停，立即点击继续也不会提前请求。普通连接失败最多再试两次；不切换域名、代理或证书策略。
- ETA 使用本次运行的实际墙钟耗时／提交页数，避免把并发请求的各自耗时相加，也避免沿用旧版慢速历史。显示约每秒处理书名数和当前并发数；网站等待时显示降速提示。
- APK 不预置书目或数据库，没有改动原有同步数据协议。

## 最终真机结果

- 同一手机前 24 页：旧版 **68.541 秒**，最终采样 **8.201 秒**，样本吞吐约 **8.36 倍**；实际表现取决于网络和站点负载。
- 退回桌面 12 秒期间，真实缓存从第 **32 页推进到第 82 页**，前台服务状态已保存。暂停后计数保持不变，继续后接续下载；旧数据库及断点兼容。
- 全目录最终 **843 页、25,266 本**全部完成，累计提交处理耗时 **247,888 毫秒，约 4 分 8 秒**。此数值包含下载重试，排除人为调试暂停；不是没有中断的一次墙钟计时。有效入库网页载荷约 4,998,998 字节。
- 全量还发现了原末页规则问题：网站末页“下一页”链接指回本页。现在仅在总数明确确认的最后一页将该自链接视为结束，非末页仍拒绝循环。已从第 842 页断点补齐最后 6 本，没有重新下载前面的页；末页行为加入原生回归。
- 导出独立测试数据库复核：`PRAGMA quick_check=ok`；25,266 个唯一链接、25,266 个唯一序号，序号为 0～25,265，没有重复链接或缺失序号；原生本地查询返回相同总数。
- Flutter 全量 **108 项通过、4 项条件跳过**，原生 **17 项通过**；静态分析无问题。结果汇总 `artifacts/yeshe-speed-research/comparison.json`，最终断点完成记录 `completion-phone.json`；首轮故障与补齐前记录保留供复核。
- 按用户选择不把下载得到的书目／数据库放入 APK；仅用于隔离测试和本机验证。测试完只删除此次创建的 `.dev` 包，正式应用未卸载或清空。
