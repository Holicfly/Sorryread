# 素若阅读桌面与手机协同开发约定

日期：2026-10-22。适用范围：当前仓库的 Windows/WPF 客户端、Flutter 手机端，以及两端共享的协议、书源规则和测试样例。

本文记录后续开发需要遵守的工程约束；技术实现参考 [Flutter 技术方案](FLUTTER_TECHNICAL_PLAN.md)，现有桌面结构参考 [桌面开发文档](DEVELOPMENT.md)。本次仅编写文档，不代表下述工程配置已完成。

## 1. 仓库与工程边界

**一个 Git 仓库，两个独立应用工程。手机端放在仓库根目录的 mobile/ 中。**

```text
ai-raed_cx_new/
├─ ReadAI.csproj               现有 Windows 工程入口
├─ App.xaml                   现有桌面应用资源入口
├─ src/                       桌面 C# 代码
├─ assets/                    桌面资源
├─ mobile/                    Flutter 手机工程
│  ├─ pubspec.yaml             手机依赖与资源声明
│  ├─ pubspec.lock             手机依赖锁定文件
│  ├─ lib/                     Dart 代码
│  ├─ android/                 Android 平台工程
│  ├─ ios/                     启用 iOS 后添加
│  ├─ test/                    自动化测试
│  └─ integration_test/        集成测试
├─ shared/                    逐步建立的跨端共享资产
│  ├─ contracts/               协议定义与版本说明
│  ├─ source_rules/            声明式书源规则
│  ├─ fixtures/                合成或合法脱敏测试样例
│  └─ assets/                  明确适用于两端的资源
├─ docs/                      开发说明与技术方案
└─ scripts/                   构建发布脚本
```

mobile/ 当前是预留目录，Flutter 工程是否初始化以 pubspec.yaml 等实际文件为准；shared/ 及其子目录按功能落地，不为目录完整性创建无用模块。

开发约束：

- 保留现有桌面工程与目录，不因手机开发整体移动、重命名或重写桌面代码。
- mobile/ 不建立第二个独立 Git 仓库，不单独初始化嵌套的 .git。
- Flutter 的 Windows 平台工程不等于现有 WPF 客户端；当前手机工程不新增 Flutter Windows 目标。
- D:\ideai\flutter_env_check 是外部环境验证项目，正式手机工程在 mobile/ 中初始化，不直接将测试项目当正式应用。
- Flutter SDK、Android SDK、JDK 等安装在仓库外，禁止复制进项目或提交到 Git。

## 2. 独立开发、构建和发布

| 内容 | Windows 客户端 | Flutter 手机端 |
| --- | --- | --- |
| 工程入口 | 根目录 ReadAI.csproj | mobile/pubspec.yaml |
| 语言与 UI | C# / WPF | Dart / Flutter |
| 源码位置 | src/、App.xaml 等现有位置 | mobile/lib/ 与平台目录 |
| 依赖配置 | csproj 中的 NuGet 引用 | pubspec.yaml 与 pubspec.lock |
| 构建运行 | 明确指定 ReadAI.csproj | 在 mobile/ 中执行 flutter 命令 |
| 发布产物 | Windows 安装包/桌面发布目录 | Android APK/AAB；后续 iOS 产物 |
| 本地数据 | Windows 应用私有数据目录 | 手机应用沙箱 |

两端独立编译、独立运行和发布，不要求安装包同日更新。手机可以离开电脑独立找书和阅读；电脑离线仅影响跨端同步。

手机端不打包 WPF 程序、不嵌入完整 .NET 运行时、不通过本地电脑代理完成日常解析。C# 和 Dart 执行代码分别维护，共享协议、规则与测试规范。

现有 .NET 版本升级、桌面架构重构和手机业务迁移分别安排、分别验证。因手机功能确需调整桌面代码时，明确关联功能和验证范围，避免混入无关改动。

## 3. 防止两个工程互相收集文件

根目录 WPF 项目使用 .NET SDK 默认文件收集规则。首次建立 Flutter 工程时，必须同时检查 ReadAI.csproj 和相关发布脚本：

1. mobile/ 中的 Android/iOS 原生文件、测试、资源与构建产物不得被桌面工程误编译或作为桌面应用内容发布。
2. shared/ 中的样例、Schema 和辅助文件不得因默认通配符意外进入桌面程序集或安装包；需要的共享资源应显式声明。
3. 根据实际项目设置检查 Compile、Page、Resource、EmbeddedResource、Content、None 以及 CopyToOutputDirectory/CopyToPublishDirectory 等项目项与复制行为。
4. 配置默认排除和必要的显式移除后，重新核查原有显式桌面资源仍能正常构建、显示和发布。
5. 排除必须覆盖正常构建和发布流程；仅设置 .gitignore 不能隔离 MSBuild。

Flutter 也只声明需要的资源，不将整个仓库根目录作为 assets 打包。共享文件在构建中通过明确的路径或可复现复制步骤接入，不依赖手工临时拷贝。

本节是工程初始化时的任务清单。本次尚未修改 csproj、发布脚本或 .gitignore，不能据此认为隔离已生效。

## 4. Git 提交与本机配置

统一在仓库根目录查看和提交变更；每次检查新增文件、依赖及产物，保留用户已有的无关修改。

| 应提交 | 不应提交 |
| --- | --- |
| C#/Dart/XAML、平台工程必要源码和配置 | bin/、obj/、mobile/build/、.dart_tool/、Gradle 缓存 |
| pubspec.yaml、应用的 pubspec.lock | 本机 android/local.properties、SDK 绝对路径 |
| Gradle Wrapper 的必要脚本、JAR 和版本配置 | Android SDK、Flutter SDK、JDK、下载缓存 |
| 协议、规则、文档、合法共享资源和样例 | 用户数据库、正文缓存、Cookie、登录凭据、私人日志 |
| 实现所需的可复现生成代码，按模块统一管理 | 发布签名私钥、密码文件、配对密钥、临时安装包 |

保留 Flutter 模板提供的 .gitignore，并按实际插件补充根目录及手机端忽略规则。不要用全局忽略所有 JAR、JSON、TXT 等方式误排除工程所需文件；忽略规则修改后使用 git status/git check-ignore 验证。

生成代码遵循模块一致的策略：需要提交时连同输入与生成命令维护；选择不提交时，必须在本地和自动构建流程中自动生成，不依赖某位开发者已有文件。

SDK 路径通过本机环境和 local.properties 管理，不将 D:\Dev 等个人路径写成团队工程的固定依赖。签名文件保存在仓库外并备份，项目仅配置引用方式。

## 5. 跨端共享与行为一致性

- shared/ 存放协议、声明式规则、样例与约定，不放依赖某一端 UI 的代码。
- 普通选择器、地址模板和受控变换可配置化；C# 特殊解析逻辑不能假定可直接由 Dart 执行。
- 两端解释同一规则子集，明确编码、URL 规范化、正文分段、字符偏移和错误语义。
- 每项书源或同步规则修改配套共用输入/输出样例，分别验证 C# 与 Dart 行为。
- schemaVersion、ruleVersion、同步协议版本和数据库迁移版本分别管理。
- 数据库物理结构不强制一致；同步传递带版本的业务 DTO，不发送 SQL、不直接覆盖另一端数据库。
- 新字段和新能力提供兼容策略，旧端不理解的内容不能在回写时被清空。

功能对照至少记录：功能名称、桌面支持、Android 支持、iOS 支持、平台差异、协议/规则能力和验证状态。未适配项如实标记，不能把桌面成功当作手机已实现。

## 6. 产品与实现约束

| 方向 | 开发约束 |
| --- | --- |
| 本地优先 | 收藏、最近阅读和进度先可靠保存本机；不依赖云账号、外部数据库或公共中继 |
| 局域网同步 | 阅读器自身提供连接，支持路由器/热点；首次配对后自动或手动增量同步 |
| 阅读进度 | 使用章节与正文语义锚点，比例兼容兜底；不以像素或两端页码直接定位 |
| 并发与删除 | 收藏、进度独立合并；取消收藏不会被旧记录复活；清理缓存不删除业务状态 |
| 手机后台 | 前台/恢复时可靠补齐，不承诺杀进程后联网立即同步；无变化时不持续扫描 |
| 现代 UI | 统一设计规范、导航、暗色和反馈；重要操作有明显入口，平台差异明确适配 |
| 轻量 | 控制依赖、WebView、内存窗口和缓存；启动不等待联网；性能用真机实测 |
| 网页边界 | HTTP 解析优先，动态网页按需启用；远程页面不能访问同步秘密或任意本地能力 |
| 平台特性 | 托盘、全局热键和透明窗口保留桌面行为；手机以符合平台能力的方式适配 |
| 隐私 | 不提交或上传个人数据；核查系统云备份、日志脱敏和安全存储配置 |

技术细节按 Flutter 技术方案执行；新增设计选择先记录清楚，不将未测的性能数字或计划功能表述为已完成结果。

## 7. 开发与验证顺序

1. 记录桌面当前构建基线和实际工具链版本。
2. 配好 WPF 文件隔离和 Git 忽略规则，再初始化正式 Flutter 工程；已存在正式工程时先检查，不覆盖重建。
3. 建手机页面样板、数据库和一个书源，验证长章节、选择复制及位置恢复。
4. 小步迁移，每项形成手机本地可用的闭环，再接入对应同步能力。
5. 每次改动运行与影响范围相符的检查，完成验证后记录通过项与未验证项。

参考命令如下，工作目录必须分清：

```powershell
# 桌面构建：仓库根目录
Set-Location D:\ideai\ai-raed_cx_new
dotnet build .\ReadAI.csproj -c Debug
```

```powershell
# 手机开发：正式 Flutter 工程创建后
Set-Location D:\ideai\ai-raed_cx_new\mobile
flutter pub get
flutter analyze
flutter test
flutter run
```

以上是后续操作示例，本次编写文档不执行工程初始化或构建。具体集成测试、代码生成、发布命令随对应功能补充；不把示例调试安装当正式发布签名验证。

| 改动范围 | 至少验证 |
| --- | --- |
| 手机 UI/业务 | 分析、相关测试和对应真机操作；有交互变化就验证返回、字号与暗色等相关场景 |
| 桌面代码或工程隔离 | 桌面构建、相关功能回归；涉及打包再检查安装包文件 |
| 共享规则/协议 | 两端契约测试；协议变化补充兼容与重复/断线/冲突验证 |
| 依赖、渲染或缓存策略 | 按影响复测 Release 包体、启动、帧时间、内存或缓存增长 |
| 纯说明文档 | 链接、命令、路径、结构和前后约束一致性 |

先完成必要检查，再扩展到确实存在风险的验证，不为纯文案或视觉常量机械增加单元测试。

## 8. 交付说明

每次交付说明：改了哪个功能、影响哪一端、是否改变共享协议/规则/数据库、做了什么验证、还有哪些限制。源码、构建、手机安装、运行交互、性能和局域网同步证据分别报告。

正式工程能安装不等于性能已达标；同一 Wi-Fi 可达不等于热点已验证；Android 成功不等于 iOS 成功。发生平台限制时说明具体替代交互，避免以“功能对齐”名义承诺系统不支持的能力。
