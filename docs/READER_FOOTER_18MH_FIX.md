## 18mh 原因和处理

现场网页 `https://18mh.net/novel/detail/7600` 返回 534 条目录。章节正文是 `main.app-content .article` 内的一组 `.line` 元素，服务器 HTML 已包含正文。旧代码只等待 `chapter-content`／`reading-content`／`read-content` 等标记，既无法识别实际容器，也没有直接利用已有 HTML，最终报动态正文加载失败。

处理内容：

1. 补充 `.article` 正文规则；将目录中的章节编号和名称规范组合，避免错误使用网页的大标题。
2. 动态源先请求并检测有效 HTML，再解析。已经包含目录／正文时，无需创建 WebView，也无需加载广告、跟踪脚本。
3. HTTP 页面缺少可读内容或遭遇请求错误时才回退到 WebView。按实际 DOM 选择器判断就绪，不再匹配 HTML 中的类名字符串。
4. 浏览器创建后通过通知触发挂载，使用完整布局视口，避免原来的屏幕外 1×1 视口影响响应式页面。浏览器被阅读背景覆盖，不拦截手势。
5. 手机验证还发现一个导航竞态：WebView 的 `currentUrl()` 已是新章节地址，但 JavaScript 中仍是旧文档，曾分别误取目录的 6 段摘要和上一章正文。现通过一次 JS 调用同时取得 `location.href`、`document.readyState` 和 HTML，只有文档地址匹配且解析完成才接受，防止目录或上一章内容串入当前章节。导航仍串行，前台跳章与预加载不会同时改写同一个浏览器。
6. 主文档连接错误显示具体原因和 VPN 覆盖应用的排查提示。未更改代理配置、证书校验或同步传输。

WebView API 依据：[Flutter 官方插件说明](https://pub.dev/packages/webview_flutter)。
