# 书架、阅读信息与内置资源调整

日期：2026-10-26。范围：`mobile/` Flutter 客户端；保留现有 WPF、同步、阅读滚动优化及其未提交修改。

## 已确认的行为

1. 保留“我的书架”标题，默认显示“收藏”；只展示收藏书籍。“最近阅读”保留现有最近十本规则。
2. 封面进度按 `(从零起算的章节索引 + 当前章内进度) / 总章数` 折算。整数百分比向下取整，避免未完成时提前显示 100%。旧阅读记录缺少目录信息时显示“待读取”；打开书籍后补全。
3. 连续点击标题五次，在普通书源和 18mh 之间双向切换，相邻两次点击间隔最多 800ms。收藏与最近阅读同时切换分组，重启应用默认普通分组。同步仍包含全部记录。
4. 阅读底部保留电量、时间和原来的页数／章节数，增加当前章节及章节名；长标题使用省略号。小屏和大字号下约束两侧文字，避免挤出屏幕。
5. 目录使用与设置弹层相同的阅读主题，文字、图标、刷新控件及拖动柄适配六种配色与夜间模式。当前章采用书签轮廓、较强字重和“正在读”标记，底色保持透明。
6. 保留系统字体；另内嵌宋体、黑体、楷体、思源黑体、霞鹜文楷。移除方正选项，旧方正设置回退系统字体。选择字体不联网、不使用用户下载目录。
7. 六款原始插画和透明书脊阴影分别保存，运行时叠加；按透明画布的可见区域裁切和对齐，保留素材比例。书架随机分配封面，同一列表重建时保持稳定，排序／筛选后避免前后相邻及上下相邻重复。

## 实施顺序及输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 1 | 现有章内位置、目录 | 附加章序号、总章数、对应章节 URL；不改变原有 `progress` 含义 |
| 2 | 步骤 1 的书籍数据 | 收藏过滤、分组切换、整本百分比 |
| 3 | 步骤 2 的可见列表、六款素材 | 保持稳定且相邻不重复的封面分配，底图与书脊叠加组件 |
| 4 | 当前章节与阅读配色 | 阅读底部章节信息、配色一致的目录 |
| 5 | 已有开源字体版本和许可 | 内嵌字体资源及离线加载，旧设置兼容 |
| 6 | 前五步结果 | 本地测试、静态分析、Android 构建与独立包实机验证 |

## 数据兼容与性能边界

- 同步 `position.progress` 继续表示当前章节内的位置；整本比例通过新增可选字段 `chapterIndex`、`chapterCount`、`bookProgressChapterUrl` 在书架计算。旧端可以忽略这些字段。旧端切换章节后保留的附加字段若与当前章节 URL 不一致，手机显示“待读取”，防止用旧索引计算错误进度。
- 书源筛选只存在于书架展示层；不改数据库查询、导出、上传或远端合并规则，不因隐藏分组删除任何记录。
- 打开书籍后保存一次已知目录信息；后续沿用现有空闲保存、长手势检查点和同步合并机制。
- 封面按显示尺寸限制解码宽度，列表继续懒加载；字体仅在选用时注册，同一进程复用，阅读滚动过程中不反复读取或校验字体大文件。
- 根项目已有 `mobile/**` 的 Compile、Page、Resource、EmbeddedResource、Content、None 排除，手机资源不加入 WPF 发布。
