# 素若阅读 Flutter 手机端技术方案

日期：2026-10-22。状态：技术路线已由用户确定为 Flutter，本文用于后续分阶段实现。尚未创建手机工程，尚无手机性能、安装包或同步真机测试结果。

## 1. 决策与目标

采用 **Flutter + Dart 开发 Android/iOS 手机端，保留现有 C#/WPF 桌面端；各端使用独立 SQLite，通过局域网加密连接同步业务数据**。

重点满足：

1. 功能逐项迁移，最终保持桌面和手机业务能力一致；遵循各平台能力边界。
2. UI 达到现代手机应用应有的视觉一致性、导航、反馈和交互完成度，参考微信、Telegram、QQ、X 的成熟设计原则，形成自己的阅读器风格。
3. 轻量、启动快、阅读流畅、控制内存和缓存增长；性能验证从第一阶段开始。
4. 阅读数据保存在本地，不依赖云账号、云数据库、中继或额外部署的服务器。
5. 电脑和手机在同一局域网或连接对方热点时，支持手动和自动同步最近阅读、收藏与阅读位置。

建议 Android 首发，iOS 从架构层预留，后续在 Mac/Xcode 与真机环境落地。Android 优先、具体同步规则、UI 数值和阶段边界为实施建议，不是用户新增的硬性验收条件。Flutter 已选定，技术验证用于调整实现方式和预算，不重新开启框架选型。

## 2. 当前客户端与复用边界

本次核对依据：`ReadAI.csproj`、`src/Data/Models.cs`、`LibraryModels.cs`、`ReaderDatabase.cs`、`src/Parsing`、`src/Search` 和现有开发文档。

| 当前资产 | Flutter 迁移方式 |
| --- | --- |
| .NET 8 / WPF / C# | 保留桌面应用；手机独立 Dart 工程，不把 WPF 引入手机 |
| HttpClient + AngleSharp 的 HTTP 解析 | 在 Dart 中实现等价的请求、编码、HTML/CSS 解析与失败处理 |
| BookSourceCatalog、BookSourceDefinition | 逐步抽出两端可解释的声明式规则，避免长期手工维护两份选择器 |
| PageParser、NovelSearchParser 依赖 WebView2 | 共用适合跨浏览器的提取脚本；浏览器生命周期、登录、懒加载和视口逻辑分别适配 |
| FlowDocument / RichTextBox 正文 | 使用 Flutter 文本布局重建，不沿用 WPF 文档对象 |
| SQLite 历史、书库、设置和缓存 | 手机独立建表；通过协议映射业务记录，不要求物理表和迁移版本一致 |
| 章节 URL + Progress 比例 | 兼容旧记录，新增跨屏幕语义锚点 |
| BookKey 为 sourceId 与 detailUrl 组合 | 定义跨语言身份规范，并保留旧键别名，防止迁移后重复收藏 |
| 收藏上限 50 本 | 合并后不能静默丢记录；实施同步前统一调整限额策略 |
| 部分书源使用 HTTP | 按域名核查 Android 明文访问和 iOS ATS 策略，不假设所有书源都是 HTTPS |
| 作者/封面/简介选择器已有部分定义，书库模型字段不足 | 迁移时完善元数据链路，缺失时有统一占位，不虚构信息 |

**共享内容是协议、规则、规范、测试数据和视觉资源；C# 与 Dart 的执行代码分别维护。** 手机不嵌入完整 .NET 运行时，不把本地电脑作为解析代理，手机离开电脑仍可独立找书和阅读。

本次不修改桌面源代码、升级 .NET、移动现有目录或推断当前构建失败。进入实施阶段后再建立桌面构建基线，逐项安排必要改造。

## 3. 技术栈与依赖策略

| 领域 | 选定方案 | 使用边界 |
| --- | --- | --- |
| 语言与框架 | Flutter stable + 随附 Dart | 实施时记录准确版本，锁定工具链与 pubspec.lock，不追预览版 |
| UI | Flutter Material 3 基础组件 + 自建设计系统 | 使用 Cupertino/平台交互处理必要差异，不引入整套重型 UI 套件 |
| 状态和依赖注入 | flutter_riverpod，Notifier/AsyncNotifier | 每个功能维护局部状态；不再叠加 Bloc/GetX 等第二套状态框架 |
| 路由 | go_router | 顶级导航、阅读页、详情页、返回栈和未来深链接 |
| 数据库 | Drift + SQLite | 类型化查询、事务、显式迁移；使用原生后台数据库连接/isolate，避免同步 SQL 阻塞界面 |
| 请求 | Dio | 超时、取消、受限并发和按用途隔离配置；书源客户端与同步客户端分开 |
| HTML 解析 | package:html | 解析 DOM 与选择器；特殊编码和清洗由规则执行器负责 |
| JSON DTO | json_serializable + 明确版本的协议模型 | 编译期生成代码；不把 Drift 表对象直接当网络协议 |
| 动态网页 | webview_flutter | 按需使用系统 WebView；不能保证隐藏或后台页面正常执行所有懒加载 |
| 阅读渲染 | Flutter Text/RichText + Sliver 惰性分块 | 首期连续滚动；锚点定位和选择功能独立封装，不预先自研整个排版引擎 |
| 平台接入 | Pigeon 生成类型化通道 + Kotlin/Swift | 封装局域网发现、平台权限和插件未覆盖的系统能力 |
| 密钥 | flutter_secure_storage | Android Keystore / iOS Keychain 对应配置；禁用云同步属性并核查备份行为 |
| 配对扫码 | mobile_scanner；电脑显示二维码 | 进入配对页才申请相机权限、初始化扫描和释放相机 |
| 封面 | 有尺寸约束的图片加载 + 限额磁盘缓存 | 普通封面不额外引入 WebView；缓存实现按实测决定是否增加专用包 |
| 测试与分析 | flutter_test、integration_test、DevTools | 共享契约测试、手机集成测试和真机 profile；Release 包测体积与启动 |

Drift 用于管理越来越重要的事务、迁移和同步数据关系。其代码生成工具是开发依赖，不等于把代码生成器装入 APK。SQLite 原生库应只有一套，按实际依赖图检查重复打包；不同时引入多套数据库框架。

列出的包是选型，不代表已验证它们在项目中的组合。建工程时核对 SDK 下限、维护状态、许可证、原生构建要求与锁定版本。Android 最低版本暂建议 API 26，iOS 暂建议 16；正式支持范围在阶段 0 根据 Flutter/插件支持和测试机确定。target SDK 按实施时工具链及发布渠道要求设置。

## 4. 架构与代码组织

采用 **按功能划分 + UI/应用逻辑/仓储分层 + 单向数据流**。普通功能不过度增加层数；阅读定位、书源执行与同步合并建立纯 Dart 领域模块，便于测试。

```text
Flutter 页面与组件
       ↓ 用户意图
Riverpod Notifier / 应用服务
       ↓
Repository（本地优先）
       ├─ Drift / SQLite / 缓存文件
       ├─ HTTP 书源执行器 / WebView 会话
       └─ 同步引擎 → 局域网传输

数据库变更 → 查询流 → 功能状态 → UI 更新
```

建议新增目录，保持现有 WPF 工程位置：

```text
mobile/
  pubspec.yaml
  lib/
    app/                  启动、路由、主题、依赖组合
    design_system/        颜色/排版/间距规范、公共组件
    core/                 共享错误、网络、平台接口、安全存储
    data/                 Drift 表、迁移、DAO、仓储实现
    features/
      bookshelf/          收藏、最近阅读、继续阅读
      search/             聚合搜索、结果和书源筛选
      book_detail/        详情、目录和选章
      reader/             正文、阅读会话、定位、设置
      sync/               配对、设备、同步状态与冲突入口
      settings/           外观、缓存、导入导出
    source_engine/        规则解释、编码、解析和特殊处理
    sync_engine/          纯 Dart 协议、版本、合并和协调器
  android/  ios/  test/  integration_test/
shared/
  contracts/              JSON Schema、协议语义与兼容策略
  source_rules/           声明式书源规则
  fixtures/               合成/脱敏输入与预期结果
  assets/                 获授权且适合两端使用的图标等资源
docs/FLUTTER_TECHNICAL_PLAN.md
```

均为拟议目录，本次不创建工程。根目录 WPF SDK 会自动包含子目录部分资源，新增 Flutter 原生目录及资源时显式核查和配置排除，避免被桌面构建或发布误收集。

Widget 不执行 SQL 或合并远端数据。界面只观察当前功能需要的状态，阅读滚动位置变化不能触发整棵应用树重建。数据库保存已确认状态，Riverpod 保存界面状态，不另建相互竞争的第二份持久化真相。

## 5. 现代 UI 设计

### 5.1 视觉与交互原则

以 Telegram/微信的清楚层级、响应直接和一致组件为参考；QQ/X 中适用的导航、列表和反馈模式可吸收。形成适合阅读的独立风格，不复制聊天/社交产品的信息密度。

- 颜色按角色定义：背景、表面、正文、次要文字、强调、错误、边框；提供亮暗两套映射。
- 排版统一标题、正文、辅助信息；APP 界面字体与用户阅读字体分开管理。
- 初始间距用 4/8/12/16/24 等级，圆角集中定义；最终视觉稿验证后调整。
- 优先清楚排版和留白，避免大量卡片嵌套、大面积实时模糊、持续发光和过重阴影。
- 转场与轻反馈暂以约 150～250ms 为起点，遵循减少动态效果设置；数据保存不等待动画。
- 支持字体缩放、无障碍语义、安全区、键盘避让、系统返回和 Android 预测返回适配。

### 5.2 信息架构

| 入口/页面 | 设计 |
| --- | --- |
| 书架 | 顶部标题和搜索入口；继续阅读；收藏/最近阅读切换；封面网格与紧凑列表按需选择 |
| 找书 | 搜索框、搜索记录、来源筛选、结果列表、每源加载状态；单源失败不阻塞其他结果 |
| 设置 | 分组列表，包含阅读、外观、设备同步、缓存、导出与关于；不添加空账户中心 |
| 书籍详情 | 封面、真实元数据、来源、阅读/收藏；目录可保留部分已加载结果并显示不完整状态 |
| 阅读 | 隐藏顶级导航；点击中央显示工具栏；目录和排版设置以面板展开；保留系统返回路径 |
| 设备同步 | 对端名称、连接状态、上次成功时间、待同步状态、立即同步和取消配对 |

手机不照搬双击切书源、悬停提示和全局热键。操作以点击、长按、明确菜单与手势实现；重要能力不能只有隐藏手势。阅读工具栏设置自动隐藏，但选中文字时不能抢占系统选择手势。

同步中、等待电脑在线和失败需区分呈现；平时轻量状态即可。收到远端新进度时不突然跳动正文。取消收藏、移除最近阅读和清理缓存分别表达。

视觉开发顺序：书架/搜索/阅读/设置的高保真设计 → 可交互页面样板 → 真机手势/字号/暗色检查 → 扩展全量功能。静态截图通过不等于交互验收通过。

## 6. 阅读器实现

### 6.1 正文显示

将正文先转换成稳定段落模型，再用惰性列表/Sliver 布局可见段落，按内容大小合并短段或拆分异常长段。避免一章建立成千上万个细碎 Span，也避免将整本书常驻内存。正文显示不依赖 WebView。

首期实现连续滚动、选中复制、字号/行距/边距、主题、章节切换和稳定恢复。跨惰性块的长范围选择是专项验证点：不能假定简单套 SelectionArea 就自然支持所有跨屏选择。若首期组件组合不满足，选择稳定的分块选择方案，并在交付前明确交互范围。

横向分页、仿真翻页、TTS、批注属于后续功能，不成为基础阅读的前置依赖。不在第一阶段引入另一套排版/脚本运行时。

### 6.2 阅读位置规范

```text
bookId / sourceId
chapterId 或 canonicalChapterUrl
contentVersion / normalizationVersion / contentHash
blockId 或段落序号 + 段内字符位置
前后文短文本锚点
fallbackRatio（0～1）
操作设备、因果版本、UTC 显示时间
```

跨端规范必须定义换行、空白处理、正文段落划分、UTF-8 编码与 SHA-256 输入。空段和有意义空白不能任意丢弃，规范化算法带版本号。字符位置统一按 Unicode 标量计数，并在渲染时转换为各端需要的偏移；C#、Dart、JavaScript 的字符串索引不能未经转换直接互传。表情、代理对、组合字符和换行都要有契约样例。

正文相同优先恢复段落/字符；正文改变时匹配上下文；失败后恢复比例并说明近似定位。各端根据本机字体和屏幕重新排版，不能同步像素、页码或滚动距离。

WPF 原有比例继续可用，新阅读后补充语义位置；不为历史升级而强制重新下载所有正文。用户只是打开书籍、接收同步或查看目录时，不生成“已读到这里”的新操作。

## 7. 书源与双端维护

### 7.1 执行流程

搜索/输入链接 → 获取详情/目录 → 解析章节 → 规范化正文 → 缓存与本地显示。HTTP 优先，确实需要页面执行时才启用 WebView。

书源请求有全局与单站并发上限、独立取消、超时、有限重试和分页安全上限；实施起点可取全局 4 个请求、单站 1～2 个，按真机与站点表现调整。退出搜索后取消过期任务，旧响应不能覆盖新界面。重试只用于适合重试的失败，不无限重复请求。

响应先按字节读取，根据响应头和页面声明判断编码；GBK 等编码需要维护良好的专用解码实现与样例，不能把所有内容强行当 UTF-8。Cookie 在各端和各书源作用域内独立管理，HttpClient 与 WebView Cookie 不假设自动互通。

WebView 按需创建，限制活跃实例，登录状态按平台能力保留；释放视图不等于随意清空 Cookie。保留合法网页访问流程，不绕过登录墙或访问限制。Android/iOS 相关 HTTP 书源策略按域名配置与实测，局域网同步始终使用加密传输。

### 7.2 共享规则机制

声明式规则包含 schemaVersion、sourceId、ruleVersion、地址模板、请求方式、编码、选择器、取 text/attribute 的方式、分页与受控 transform 标识。公共规则不能包含用户 Cookie、令牌或私密请求头。

两端实现约定的选择器/正则/URL 解析子集；不同运行时不支持的表达式不能无声退化。Base64、目录隐藏规则等特殊变换通过命名处理器实现，分别编写 C#/Dart 代码与同一份输入/输出样例。不是把现有 C# 代码简单转换成 JSON 就能全量共享。

规则先随应用打包，后续可支持用户主动导入或配对设备传输声明式规则，验证版本和能力；不依赖远程规则服务器，不直接执行网络下发的任意代码。网站 JS 提取脚本与平台加载会话分离，脚本是否跨端等价需实际验证。

通过共享 fixtures 检查详情、目录、文本、链接、编码、分页及错误语义。使用合成 HTML 或合法脱敏样本，不提交真实 Cookie、用户数据库或无权分享的正文。

## 8. 局域网同步

### 8.1 拓扑与发现

电脑 WPF 阅读器内嵌 ASP.NET Core Kestrel HTTPS 接入，随阅读器进程启动或停止；手机使用专用 Dio 客户端主动连接。无需独立部署服务或购买证书。传输分服务端/客户端，业务数据仍双向合并，电脑不是唯一权威。

发现采用 DNS-SD/mDNS：Android NSD、iOS Bonjour，Windows 提供服务广播。Flutter 使用类型化平台适配接口，不在整个应用散布插件调用。扫码或手动地址作为发现失败的备用入口，二维码可带多个候选地址；不能绕过 AP 隔离或防火墙。

覆盖同一路由器、电脑连手机热点、手机连电脑热点；网络是否有互联网不影响同步。处理网卡变化、IP 变化、VPN、IPv4/IPv6 和 Windows 私有网络防火墙规则。只在启用同步时监听必要网络接口，不向公网做端口映射。

Android 17 且 target SDK 37 及以上按要求请求 ACCESS_LOCAL_NETWORK，旧版本按对应平台规则处理；iOS 配置 NSLocalNetworkUsageDescription 与具体 NSBonjourServices。拒绝权限时仍能本地阅读，并给出可操作的状态说明。热点实现和平台权限必须真机测试。

### 8.2 配对与身份

电脑主动开启限时配对，展示地址、协议版本、证书公钥指纹及一次性随机令牌的二维码。手机扫描后先验证带外获得的指纹，再交换设备身份与专属凭据；电脑提供可见的配对确认。手动输入地址也需要带外指纹核对，不静默信任首次遇到的证书。

使用成熟 TLS 与系统密码能力；设备身份和证书固定限定在同步客户端内。实现时证明 TLS 身份验证发生在发送凭据和业务数据之前；不得用全局无条件接受证书的回调。网站 HTTPS 不共享局域网自签名信任配置。

后续使用设备专属高熵凭据认证，存入系统安全存储；支持撤销配对、吊销令牌和重新配对。二维码令牌一次性、有有效期、有尝试次数限制；证书更换按已认证轮换流程处理，否则要求重新配对。不额外自制一套密码算法或重复叠加未明确必要的签名机制。

### 8.3 首期数据范围

| 数据 | 行为 |
| --- | --- |
| 收藏 | 基本书籍/来源资料、添加与取消 |
| 最近阅读 | 每本书最后有效阅读信息与列表可见状态；普通网页文章也有独立身份 |
| 阅读位置 | 章节、语义锚点、备用比例和版本 |
| 删除/清除 | 区分跨端移除记录与仅清理本机缓存 |
| 正文、完整目录和封面文件 | 首期不默认全量传输，后续可选；元数据同步成功不代表正文离线可读 |
| 搜索记录、外观与排版偏好 | 首期各端独立，后续选择性同步 |
| 网站 Cookie、登录凭据、窗口与托盘设置 | 首期不同步，各端独立 |

近期列表显示上限不能当作删除另一端记录的依据。合并收藏超过现有 50 本时不得丢弃；在同步功能交付前调整桌面限制和显示逻辑。没有正文缓存且书源不可达时保留书籍与位置，显示正文暂不可用。

### 8.4 标识、事务与增量协议

书籍身份基于 sourceId 与规范化详情 URL，文章身份基于规范化文章 URL。规范明确大小写、端口、fragment 与查询参数处理，不随意删除影响身份的参数；不同来源同名书不自动合并。旧 BookKey 保存映射，避免重新生成身份造成重复记录。

每台设备分配稳定 deviceId，每条变更包含原始设备 originDeviceId、设备内单调 originSeq、changeId、entityId、字段组、因果上下文与 payload。跨语言序号使用约定的十进制字符串表示，时间统一 UTC，禁止依赖 C# 特有 JSON 格式。

业务数据和 Outbox 在同一数据库事务提交；接收去重、合并和游标推进同样原子完成。按原始设备序号确认连续接收范围，不能跳过缺失序号后直接确认最大值。转发手机产生的记录时保留原始身份，防止未来多设备时漏传或循环生成变更。接收数据不产生新的本地阅读事件。

```text
能力/版本握手 → 交换已知版本与接收游标
→ 分批上传本地变化 → 事务提交并确认
→ 分批获取对端变化 → 事务提交并确认
→ 对账/继续下一批 → 更新本次同步状态
```

协议初始包含 hello、changes/push、changes/pull 和 snapshot 能力，使用明确 DTO/JSON Schema；具体 HTTP 方法与路径在实现前补充接口契约。先提供可工作的批量 HTTPS 请求，不以 WebSocket、长连接或二进制协议作为首期前提。

请求限制批量条数、总字节、字段长度与解析深度；未知字段不导致旧端回写清空新数据，不支持的必要能力应明确拒绝相应操作。网络中断后从已确认游标继续，不直接覆盖数据库文件。

首次同步或日志压缩后的全量对账使用带一致水位的快照，再补快照之后的增量；快照没有某条记录不等于要求删除它。删除标记保留到可信确认或压缩成版本摘要。长期离线设备需重新对账时明确执行，不能只因保存天数到期就把旧状态重新导入。

### 8.5 合并规则

收藏、阅读位置和最近阅读可见性分别版本化。使用每字段组的轻量版本向量判断“后续修改”还是“并发修改”；仅有时间戳或 HLC 不能证明因果关系。设备时间用于显示和辅助排序，不能独自决定所有冲突。

| 场景 | 规则 |
| --- | --- |
| 收藏不同书 | 合并 |
| 取消收藏 vs 未修改旧收藏 | 取消传播，旧副本不能复活 |
| 收藏与取消真正并发 | 取消优先；用户看到合并结果后仍可再次收藏 |
| 已知之前进度后继续阅读 | 后续有效阅读位置替代旧位置 |
| 两端离线同时阅读同一本书 | 保留两个候选，不自动跳动；恢复时让用户选择，选择产生覆盖候选的新版本 |
| 回看前面章节 | 是有效位置，不取最大章号或最大比例 |
| 移除最近阅读 | 同步列表可见性；保留必要版本信息，防止旧记录复活 |
| 清理缓存 | 本机行为，不删除收藏/进度 |

冲突集合对相同候选去重，明确候选上限和可解释的处理方式。三端合并、不同接收顺序、重复和转发都要收敛到同一状态。

### 8.6 自动/手动与生命周期

手动“立即同步”与自动触发使用同一协调器，单设备会话串行，合并重复触发。自动同步在已配对、用户启用且对端可达时工作：启动/恢复前台、前台网络变化、收藏改变和阅读位置稳定后触发。

阅读中先保存本地进度；上传使用防抖与批次，不逐滚动发送。防抖必须有最大延迟/阶段性保存，不能因持续滚动而一直不落盘。进入后台前可靠提交本地，网络同步尽力完成；被杀进程后的下次启动继续。

不常驻手机前台服务、不持续扫描网段。前台发现短时间尝试后退避，离线无变化时不持续唤醒。Android/iOS 后台限制依然适用，不承诺杀进程或长期锁屏后联网就立即同步。电脑不在线时，各端仍能独立使用。

## 9. 存储、缓存与隐私

手机建议包含 books、reading_positions、favorite_states、recent_states、chapter_cache、settings、paired_devices、sync_changes、peer_cursors 等逻辑表。冲突候选和因果元数据独立管理；配对密钥只保存安全存储引用。具体建表由首期契约确定。

正文按需存储，元数据与大正文查询分离；封面落盘，内存只保留显示尺寸解码结果。正文缓存 LRU 可淘汰，收藏、位置、未确认变更和冲突候选不能因缓存超限被删。允许将用户明确下载的离线内容标为保留，清理前显示影响。

配置正文/封面缓存容量、日志轮转和用户清理入口；容量数值在阶段 0 测量后确定，不能无限增长。用户数据放应用私有目录，导入/导出通过系统文件入口，路径不作为跨端身份。

默认无云账户、云同步、第三方统计或自动上传日志。核查 Android Auto Backup/data extraction rules、iOS 文件备份排除和 Keychain 非同步配置，避免受应用控制的阅读数据与配对秘密自动进入系统云备份。用户主动导出到云盘属于用户选择，默认不引导这样做。

不以本地优先宣称 SQLite 已静态加密。首期应用沙箱保护数据库，安全存储保护密钥；如以后要求数据库静态加密，再单独验证对应方案。日志脱敏，不记录配对令牌、Cookie 或正文。

## 10. 轻量与性能方案

### 10.1 实现约束

- 启动只加载本地首页所需数据；不等网络、不初始化 WebView/相机、不扫描全部书籍或同步大目录。
- 阅读页只更新必要状态，正文内容与工具栏/同步提示隔离；稳定 key，避免频繁全量布局。
- 数据库用后台连接；大 HTML 解析、正文清洗、哈希等测量到明显开销时转工作 isolate，限制任务队列。不是每次请求都新建 isolate。
- 当前章及少量相邻章作为有限内存窗口；预取可取消，移动网络和弱机能收缩。
- 封面按实际尺寸解码，长列表惰性创建，不内置大字体、完整浏览器引擎或重型动效素材。
- 控制透明合成、模糊、阴影和大面积剪裁；用 profiler 判断热点，不凭“Flutter 默认很快”免测。
- 阅读可选保持屏幕常亮，离开阅读页恢复；无变化的后台不进行周期轮询。

### 10.2 测量口径与阶段门槛

| 指标 | 测量方式与验收方向 |
| --- | --- |
| 包体 | Android 单 ABI Release APK 与 AAB 预估下载大小分别记录，安装后大小单列；检查字体/资源/原生库组成 |
| 启动 | 真机进程冷启动到本地书架可操作，首装与日常分开；记录重复样本中位数及 P95，不把启动图消失当完成 |
| 正文流畅度 | profile 模式真机滚动与切章，检查 UI/raster 帧时间；60Hz 预算约 16.7ms，120Hz 约 8.3ms，持续卡顿必须定位 |
| 内存 | 稳态阅读、进入/退出 WebView、往返页面和长时间切章；Android PSS 包含相关进程开销，不只看 Dart 堆 |
| 缓存 | 反复使用达到配置上限后可控淘汰，不无限增长，也不误删用户状态 |
| 电量 | 无变化离线/后台没有持续连接扫描或唤醒；读书与同步分别观察 |

阶段 0 固定一台中低配置 Android 真机、系统版本、构建模式与合成样例，覆盖 1 万字、10 万字异常长章节和大目录。形成首份基线后给出可实现的包体、启动、内存数字预算并写入性能记录；本方案不把未经测量的“几 MB、秒开”写成已保证结果。后续依赖和 UI 变更与同口径基线比较，性能退化需说明。

工具采用 Flutter DevTools、app size analysis 与 Android 系统内存/启动分析；动画分析使用 profile，最终安装体积和启动检查使用 Release，不能以 Debug 包或模拟器代表交付表现。

## 11. 分阶段交付

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0. 工具链与关键验证 | 建 Flutter 工程，样板 UI、一个 HTTP 书源、长章节/选中/定位、Drift、电脑 HTTPS 扫码小样 | Release 可安装；热点直连；定位与中文选择可用；产出首份体积/启动/帧/内存基线 |
| 1. 基础阅读 | 书架、最近阅读、收藏、搜索/详情/目录、连续阅读、排版设置、本地缓存 | 手机独立找书阅读；断网读已有缓存；重启恢复；深色/大字号/返回栈验收 |
| 2. 手动同步 | 桌面新增日志/定位/连接，手机配对与三类数据双向合并 | 重复、断线、并发、取消收藏、旧比例与新锚点、撤销配对、协议差异测试通过 |
| 3. 自动同步 | 前台发现、网络变化、防抖/最大延迟、退避与状态 UI | 两种热点和路由器；拒绝权限/电脑离线；不阻塞阅读或造成持续唤醒 |
| 4. 逐项补齐 | 其余书源、动态网页与登录、导出/分享、音量键、阅读细节 | 每项共享样例和两端功能对照通过，动态页面必须手机实测 |
| 5. 扩展 | iOS/平板、可选正文传输、更多阅读模式 | 对应真机、签名/分发、权限、后台行为和性能完成验证 |

不估算未经验证的固定周数。每阶段形成可审查差异和可安装产物，桌面升级与手机迁移分开验证；无需一次改造所有 C# 业务。iOS 如需提前交付，应调整阶段安排，不改变 Flutter 路线。

透明窗口、托盘、全局热键保持 Windows 特性。Android 悬浮阅读为单独评估的后续能力；iOS 不承诺任意其他 APP 上方的同等透明窗口。功能对齐指用户目标等价，平台差异在对照表记录。

## 12. 验证与风险控制

| 风险 | 对策/证据 |
| --- | --- |
| C#/Dart 规则漂移 | 声明式规则、共享输入/输出、逐源验证；同一修复单关联两端实现 |
| 同步代码双写且行为不一 | 共用 JSON Schema 和因果/合并测试向量，覆盖随机接收顺序、三端转发与重复 |
| 长文本与跨段选择卡顿/异常 | 阶段 0 真机测试，调整正文分块与选择实现，持续记录帧和内存 |
| WebView 内存和站点差异 | HTTP 优先、按需实例、真机加载/登录/懒加载验证 |
| 平台插件变化 | 限定依赖、锁版本、平台接口封装、定期有目的地升级 |
| 缓存清理误删状态 | 缓存与收藏/进度/未确认变更明确分离，事务和迁移测试 |
| 系统备份或日志带出数据 | 备份排除、安全存储属性、日志脱敏专项检查 |
| 旧端不认识新协议 | 能力协商、兼容窗口、不支持时可解释停止相应操作；本地功能继续可用 |

验证层次：Dart 单元测试负责解析、定位与合并；Drift 测试负责事务/迁移；C# 与 Dart 共跑契约样例；双进程验证接口和重试；真机负责热点、权限、生命周期、长文本和性能。仅修改方案文档不运行无关构建，不把设计建议写成已通过的测试结果。

每项功能维护“桌面/Android/iOS 支持情况、共享规则版本、协议能力、平台差异、验证状态”。功能同步靠明确契约和共同用例维持，不要求两个安装包永久同日更新。
